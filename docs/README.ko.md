# cudoc 사용 가이드

[English](./README.md) | **한국어** · [프로젝트 홈](../README.ko.md)

Markdown 문법 확장과 문서 임베드가 두 핵심 기능입니다. 독립 HTML은 지원하는 모든 문서 호스트와 함께 또는 단독으로 사용하는 선택적 추가 출력입니다. 문서 호스트는 기본 사이트를 빌드하고 제공하는 정적 사이트 생성기와 웹 프레임워크를 통칭합니다. 설정은 사이트 구성에서 관리하고, 문서 작성자는 Markdown과 cudoc 표기만 사용합니다.

## 순서대로 익히기

1. [시작하기](../README.ko.md#시작하기): 문서를 작성하고 HTML로 생성합니다.
2. [Markdown 문법](./syntax.ko.md): 기능별 문법을 선택하고 알림·앵커·배지·표를 작성합니다.
3. [문서 임베드](./embedding.ko.md): 문서를 수집하고 섹션 선택·요약 표·찾기·바꾸기를 적용합니다.
4. [AST 데이터셋](./dataset.ko.md): 컴파일한 문서를 용도에 맞게 필터링합니다.
5. [독립 HTML](./html.ko.md): 기본 사이트와 함께 파일을 생성하고 하이퍼링크 정책을 선택합니다.

## 호스트 선택

| 호스트                    | 가이드                            | 문서 형식                        |
| ------------------------- | --------------------------------- | -------------------------------- |
| 기존 Next.js 애플리케이션 | [Next.js와 MDX](./next-mdx.ko.md) | `.md`, `.mdx`                    |
| Docusaurus 사이트         | [Docusaurus](./docusaurus.ko.md)  | 형식 감지를 적용한 `.md`, `.mdx` |
| Nextra 사이트             | [Nextra](./nextra.ko.md)          | 형식 감지를 적용한 `.md`, `.mdx` |
| VitePress 사이트          | [VitePress](./vitepress.ko.md)    | `.md`; React MDX 미지원          |
| Eleventy 사이트           | [Eleventy](./eleventy.ko.md)      | `.md`; React MDX 미지원          |

문법 확장만 사용하면 호스트 설정으로 충분합니다. 문서 간 임베드는 호스트 실행 전에 수집과 준비 단계를 추가합니다. 다시 실행해야 하는 시점은 [임베드 가이드](./embedding.ko.md)에서 안내합니다.

독립 HTML은 위 다섯 호스트 연동과 함께 사용할 수 있습니다. 호스트의 수집 라이브러리를 재사용해 고유 문법과 준비된 임베드를 유지하고, 로컬 링크·배포 URL 연결·하이퍼링크 제거 중에서 선택합니다. [기존 사이트와 함께 생성](./html.ko.md#기존-사이트와-함께-생성)을 참고하세요.

## 개발자를 위한 문서

[API 레퍼런스](./api-reference/README.ko.md)에서 import 경로, 시그니처, 기본값, AST 메타데이터, 저장 방식, 컴파일 순서를 확인할 수 있습니다. [실행 예제](../examples/README.md)는 실제 호스트 연동과 검증 명령을 제공합니다.

현재 범위는 문법 확장, 임베드, AST 필터링, HTML 생성입니다. 링크 감시와 별도 Docs 프로젝트의 대체는 포함하지 않습니다. 호스트 문법 지원은 가이드에 명시한 형태를 기준으로 하며, 임의의 호스트 플러그인이나 동적 컴포넌트가 자동으로 공통 문서로 변환되지는 않습니다.
