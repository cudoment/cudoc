# cudoc

[English](./README.md) | **한국어**

**한 번만 쓰고 어디서나 다시 쓰세요. 문서에도, 사이트에도, 인덱스에도 원본은 하나만 남습니다.**

cudoc은 지금 쓰고 계신 문서에 세 가지를 더합니다. Markdown 문법 확장, **문서 임베딩**, 독립 HTML 출력입니다. 쓰시던 정적 사이트 생성기에 그대로 붙고, 작성자는 하던 대로 Markdown만 쓰면 됩니다. Next.js, Docusaurus, Nextra, VitePress, Eleventy를 지원합니다.

예전보다 더 중요해진 이유가 있습니다. 이제 문서를 읽는 쪽이 사람만이 아니기 때문입니다. 검색 파이프라인과 에이전트와 모델이 사람보다 훨씬 자주 문서를 읽습니다.

---

## 문제: 같은 문장이 열한 군데에 흩어져 있습니다

문서가 쌓이면 여러 페이지에 동시에 들어가야 하는 사실이 생깁니다. 요청 한도, 필요한 권한, 지원 버전 표 같은 것들입니다. 그래서 복사합니다. 그리고 사본 하나를 고치는 순간 나머지 열 개가 조용히 틀린 내용이 됩니다.

**cudoc은 사본을 없앱니다.** 사실은 한 문서에만 두고, 나머지는 그것을 가리킵니다.

````md
```cudoc-embed
sources: [reference.md#limits]
```
````

빌드할 때 cudoc이 진짜 내용을 끌어옵니다. 독자는 완성된 페이지를 읽고, 작성자는 문단 하나만 관리합니다.

## "그냥 공용 컴포넌트로 만들어서 임포트하면 안 되나요?"

됩니다. 그리고 그렇게 하면 사본도 실제로 사라집니다. MDX 계열 호스트는 조각 파일을 만들어 임포트할 수 있고, markdown-it 계열 호스트에는 같은 일을 하는 include 지시자가 있습니다. 중복이 유일한 문제였다면 여기서 이야기가 끝나도 됩니다.

끝나지 않는 이유는 임포트와 임베드가 서로 **다른 것을 만들어 내기** 때문입니다.

임포트는 **참조인 채로 남습니다.** 페이지에는 컴포넌트 노드 하나가 들어가고, 그 컴포넌트가 등록된 호스트가 렌더링할 때에야 글이 나타납니다.

```mdx
import Limits from "./_limits.mdx"

<Limits />
```

임베드는 **아무것도 렌더링되기 전에 해석됩니다.** 빌드 시점에 cudoc이 이 블록을 원본 문서의 실제 제목과 문단과 표로, 평범한 문서 노드로 바꿔 놓습니다.

````md
```cudoc-embed
sources: [reference.md#limits]
```
````

이 차이 하나가 나머지를 전부 결정합니다.

|                              | 공용 컴포넌트                               | `cudoc-embed`                                        |
| ---------------------------- | ------------------------------------------- | ---------------------------------------------------- |
| 재사용의 단위                | 파일 하나 전체                              | 실제 페이지의 아무 절이나. 앵커, 제목, 깊이로 고름   |
| 사실이 놓이는 자리           | URL도 앵커도 없고 목차에도 없는 조각 파일   | 독자가 링크할 수 있는 정식 문서                      |
| 작성 방식                    | `.mdx`와, 쓰는 페이지마다 붙는 import 한 줄 | 평범한 `.md`. 가져올 것도 등록할 것도 없음           |
| 호스트 사이의 이동           | 호스트마다 표기가 다름                      | 여섯 호스트에서 같은 블록                            |
| 가져온 내용 손보기           | props를 붙이거나 조각 파일을 하나 더 만듦   | `replace`로 이 페이지에서만 바꿔 씀. 원본은 그대로   |
| 파생해서 보여 주기           | 가져오는 것만 가능                          | `render: { type: table }`로 제목 요약 표를 만들어 냄 |
| 검사                         | 빌드가 하나씩 실패하며 알려 줌              | `cudoc check`가 깨진 원본과 앵커를 한 번에 보고      |
| 호스트 밖의 소비자가 받는 것 | 렌더링할 수 없는 컴포넌트 이름              | 글 그 자체                                           |

### 재사용하려고 문서를 조각낼 필요는 없습니다

조각 파일 방식은 **재사용의 단위를 파일의 단위와 같게** 만듭니다. 절 하나를 공유하려면 그 절을 `_limits.mdx`로 도려낸 다음, 원래 있던 페이지로 다시 임포트해 와야 합니다. 몇 번 반복하면 정작 원본 글은 아무도 직접 열어 보지 않는 조각들에 흩어지고, 진짜 페이지는 조립 명세서가 됩니다.

cudoc은 문서를 통째로 둡니다. `reference.md`는 URL을 가진 페이지 그대로이고, `#limits`는 누구나 링크할 수 있는 앵커 그대로이며, 재사용은 재사용이 일어나는 자리에 적힙니다. 어디까지를 떼어 쓸지 미리 정해 둘 필요가 없고, 그 경계가 바뀌어도 구조를 다시 짜지 않아도 됩니다.

### 그리고 가져온 내용은 진짜 글입니다

바로 다음 절이 이 사실 위에 서 있습니다. 컴포넌트 노드는 호스트가 아닌 모든 것에게 불투명합니다. 독립 HTML 내보내기도, AST 데이터셋도, 말뭉치를 읽는 검색기도 그 안을 볼 수 없습니다. cudoc이 해석해 놓은 결과는 실제 내용이므로, 어느 도착지든 똑같이 완성된 문서를 받습니다. → [문서 임베딩](./docs/embedding.ko.md)

## 두 번째 독자: 검색 파이프라인

중복된 문서는 예전에도 유지보수 비용을 늘렸습니다. 이제는 **검색 인덱스까지 망가뜨립니다.**

> **중복된 문서 위에 RAG 파이프라인을 올리면 거의 똑같은 사본 열한 개가 전부 청크가 됩니다.** 질의 하나가 그중 여러 개를 끌어와 같은 문장을 반복하느라 컨텍스트를 쓰고, 정작 답이 들어 있는 청크의 관련도 점수는 그만큼 묻힙니다. 한 페이지만 고치고 나머지를 놔뒀다면 더 나쁩니다. 인덱스 안에서 낡은 사본이 최신 내용과 나란히 경쟁하는데, 모델에게는 둘 중 어느 쪽이 지금 맞는 값인지 가릴 방법이 없습니다.

원본을 하나로 모으면 이 문제는 뿌리부터 사라집니다. 그 위에 cudoc이 기계 쪽으로 네 가지를 더 줍니다.

- **가리키는 대신 펼쳐서 내보냅니다.** 임베드는 빌드할 때 펼쳐지므로 크롤러나 검색기가 읽는 HTML은 빠진 곳 없는 문서입니다. 작성자는 참조만 관리하고 기계는 전문을 받습니다. 둘 중 하나를 고르실 필요가 없습니다.
- **글자 수가 아니라 의미로 자를 수 있습니다.** `cudoc dataset`은 컴파일한 문서를 AST JSON과 매니페스트로 내보내면서 제목 계층과 앵커와 절 경계를 그대로 살립니다. 문장 중간에서 끊기는 고정 길이 창 대신 절 하나를 청크로 삼을 수 있습니다. 설정 한 줄이면 `code` 블록이나 내부용 컴포넌트를 인덱스에서 뺄 수 있습니다. → [AST 데이터셋](./docs/dataset.ko.md)
- **MCP 서버가 그대로 서빙할 수 있는 말뭉치가 나옵니다.** 중복이 없고, 임베드가 펼쳐져 있고, 필요 없는 노드가 걸러져 있고, `문서#앵커`까지 주소가 잡힙니다. 보통은 수집 스크립트를 따로 짜서 만들어야 하는 정제 상태입니다. "요청 한도가 얼마죠?"라는 질문에 페이지 하나가 아니라 절 하나로 답하고, 그 답이 어느 앵커에서 왔는지까지 같이 돌려줄 수 있습니다.
- **모델이 그대로 읽을 수 있는 원본을 남깁니다.** 작성자가 컴포넌트를 import하거나 등록하는 일이 없으므로, 모델이 집어삼키는 `.md` 파일은 사람이 읽는 그 글과 똑같습니다. 걷어낼 JSX도, 렌더링해야만 생기는 런타임 상태도 없습니다.

에이전트가 문서를 쓰게 하신다면 `cudoc check --format json`이 깨진 링크와 앵커와 이미지와 임베드를 한 번에, 기계가 읽는 형태로 돌려줍니다. 사람이 빌드 로그를 들여다보지 않아도 고치는 순환이 닫힙니다. → [참조 검사](./docs/check.ko.md)

결국 전부 단일 원본을 위한 것입니다. 아래 내용은 그것을 실제로 굴러가게 만드는 장치들입니다.

## 쓰시는 생성기를 고르세요

각 가이드는 설치, 설정, 수집 연결, 빌드 순으로 번호를 매긴 절차입니다. 모든 단계가 그대로 복사해 쓸 수 있는 명령이나 파일이라, 직접 따라 하셔도 되고 코딩 에이전트에게 그대로 넘겨 설정을 맡기셔도 됩니다.

| 쓰시는 사이트          | 가이드                                       | 설치                                                |
| ---------------------- | -------------------------------------------- | --------------------------------------------------- |
| **Next.js**            | [Next.js 설정 →](./docs/next.ko.md)          | `@cudoment/cudoc cudoc-remark`                      |
| **Docusaurus**         | [Docusaurus 설정 →](./docs/docusaurus.ko.md) | `@cudoment/cudoc cudoc-remark cudoc-docusaurus`     |
| **Nextra**             | [Nextra 설정 →](./docs/nextra.ko.md)         | `@cudoment/cudoc cudoc-remark cudoc-nextra`         |
| **VitePress**          | [VitePress 설정 →](./docs/vitepress.ko.md)   | `@cudoment/cudoc cudoc-markdown-it cudoc-vitepress` |
| **Eleventy**           | [Eleventy 설정 →](./docs/eleventy.ko.md)     | `@cudoment/cudoc cudoc-markdown-it cudoc-eleventy`  |
| **아직 생성기가 없음** | [독립 HTML →](./docs/export.ko.md)           | `@cudoment/cudoc cudoc-export`                      |

아직 생성기가 없으시다면 마지막 줄부터 보세요. 빈 디렉터리에서 명령 두 번과 문서 두 개면 사이트 하나가 나옵니다. → [첫 사이트 만들기](./docs/export.ko.md#빈-디렉터리에서-첫-사이트-만들기)

설치 열에는 cudoc 패키지만 적었습니다. 호스트 자체가 요구하는 의존성은 각 가이드 1단계에 함께 나옵니다. ESM이고 Node.js 20 이상이 필요합니다.

모든 호스트가 `.md`를 받습니다. MDX 계열 세 호스트는 `.mdx`도 받고, 어느 쪽인지는 파일 확장자로 파일마다 갈립니다. cudoc의 기능은 두 형식에서 똑같이 동작합니다. → [`.md`와 `.mdx` 선택](./docs/README.ko.md#md와-mdx-선택)

독립 HTML은 다른 것들 대신 고르는 일곱 번째 선택지가 아닙니다. 어느 호스트를 쓰시든 같은 수집 결과를 재사용해 **추가로** 뽑아낼 수 있는 출력입니다. → [기존 사이트와 함께 생성](./docs/export.ko.md#기존-사이트와-함께-생성)

## 무엇을 얻게 되나

### 컴포넌트 없이도 더 많이 담는 Markdown

작성자는 React 컴포넌트를 가져오지도, 등록하지도 않습니다. 그냥 Markdown입니다.

```md
## 준비 사항 (#requirements) (@New)

> [!NOTE] 시작하기 전에
> 계정과 액세스 토큰을 준비하세요.

| 항목 | 필요한 것                                     |
| ---- | --------------------------------------------- |
| 접근 | - 계정<br />-- 이메일 인증<br />- 액세스 토큰 |
```

명시적 제목 앵커, 배지, 제목이 붙는 콜아웃, 표 셀 안의 중첩 목록입니다. 기능마다 cudoc 문법과 호스트 고유 문법 중 하나만 쓰거나 둘 다 받아들이도록 고를 수 있습니다. 기존 페이지를 한 줄도 손대지 않고 cudoc을 들이실 수 있다는 뜻입니다. → [Markdown 문법](./docs/syntax.ko.md)

### 통째로가 아니라 골라서 가져옵니다

| 하고 싶은 것                      | 쓰는 방법                                          |
| --------------------------------- | -------------------------------------------------- |
| 문서 전체                         | `sources: [reference.md]`                          |
| 한 절과 그 아래 절까지            | `sources: [reference.md#limits]`                   |
| 아래 절을 뺀 한 절                | `includeChildren: false`                           |
| 제목만 모은 요약 표               | `select: { depth: 2 }`와 `render: { type: table }` |
| 같은 내용을 이 페이지 문맥에 맞게 | `replace: [{ find: "...", replace: "..." }]`       |

원본 문서는 손대지 않습니다. → [문서 임베딩](./docs/embedding.ko.md)

### 문서 한 벌로 도착지 세 곳

사이트와 전달용 HTML 묶음과 기계가 읽는 AST 말뭉치가, 같은 Markdown에서 같은 방식으로 나옵니다.

| 출력         | 명령                 | 쓰임새                                                    |
| ------------ | -------------------- | --------------------------------------------------------- |
| 기존 사이트  | 평소 쓰시던 빌드     | 사람이 읽는 운영 문서                                     |
| 독립 HTML    | `cudoc-export build` | 오프라인 전달, 망분리 환경 검토, 정적 배포                |
| AST 데이터셋 | `cudoc dataset`      | RAG 파이프라인, 검색 인덱스, MCP 서버, 에이전트 참고 자료 |

HTML 출력은 하이퍼링크를 세 가지 방식으로 다룹니다. 로컬 파일로 잇거나, 배포 URL로 바꾸거나, 아예 없앱니다. 덕분에 같은 내용을 디스크에서 열든 웹에 올리든 그대로 동작합니다.

## 기여하기

```sh
npm ci
npm run build
npm test
```

`npm test`는 세 계층을 돌립니다. 패키지 단위 테스트, 각 예제의 실제 컴파일러로 공유 픽스처를 통과시키는 통합 검사, 그리고 빌드된 예제 사이트를 직접 읽는 검사입니다. 전제를 갖추지 못한 계층은 실패하는 대신 그 전제를 만드는 명령과 함께 건너뜁니다. [`tests/README.md`](./tests/README.md)를 참고하세요.

호스트 예제는 자체 lockfile로 따로 설치합니다. API나 사용 흐름을 바꾸실 때는 해당 가이드와 API 레퍼런스도 같은 변경 안에서 함께 고쳐 주세요.

## 릴리스 노트

### 0.5.0

- HTML 사이트와 나란히 PDF와 Word를 내보냅니다. 호출 한 번, 디자인 토큰 한 벌에서 나옵니다.
- `cudoc-pagebreak` 펜스가 페이지를 나누는 형식에서 쪽을 넘기고 사이트에서는 아무것도 보이지 않습니다.
- 문서 집합을 한 권으로 묶은 파일로도 내보내며, 문서 사이 링크가 그 안에서 해석되고 PDF와 Word 모두 표지와 목차로 시작합니다.
- `page` 설정 하나로 PDF와 Word가 같은 용지, 머리글과 바닥글, 제목 앞 쪽 나누기, 넓은 표의 가로 쪽, 인쇄된 링크 주소를 갖습니다.
- `annotations: true`를 켜면 HTML 사이트에 메모 런타임이 실립니다. 파일을 받은 사람이 글자나 블록을 골라 메모를 남기고 파일이나 공유 토큰으로 돌려줄 수 있고, `cudoc-export annotations`가 그 메모를 원문 줄 번호가 붙은 사실 기록 보고서로 정리합니다.
- `themeSwitch: true`를 켜면 HTML 사이트 머리글에 시스템·라이트·다크 버튼이 생기고 선택을 브라우저가 기억합니다. 켜지 않으면 기본 스타일이 스크립트 없이 시스템 설정을 따릅니다.
- MDX 호스트에서는 임베드된 절이 페이지가 컴파일될 때 접합되므로, 그 안의 컴포넌트는 호스트 자신의 컴포넌트 매핑으로 렌더링되고 코드 블록은 호스트의 강조기에 닿습니다. 임베드 플러그인은 더 이상 HTML 문자열을 렌더링하지 않고 `cudoc-remark/runtime`은 없어졌으며, `cudoc-remark/loader`가 재수집을 개발 서버와 빌드 캐시에 알립니다. `cudoc check`가 원본 파일에 import가 남아 있는 복사된 컴포넌트를 보고합니다.
- 표 임베드가 열을 직접 정의합니다. 각 셀의 글자가 어디서 오는지(절 제목, 첫 문단, 상위 제목, 절 안 표의 셀, 또는 수집 설정에 등록한 함수), 무엇으로 연결되는지, 어느 폭을 유지해야 하는지를 적을 수 있고, 정의한 열이 비워 둔 셀을 `cudoc check`가 모두 보고합니다.
- `roots: [{ dir, base }]`로 여러 디렉터리를 하나의 라이브러리로 수집하며 각각 자기 URL 접두어 아래에 놓입니다. `/docs/…`와 `/terms/…` 링크, 임베드 원본, 내보내기가 모두 같은 문서를 가리킵니다. `exclude`는 문서가 아닌 파일을 빼고, `private`는 내부용 문서를 수집·검사는 하되 내보내기와 데이터셋에서 빼며, `externalPaths`는 같은 도메인에서 다른 애플리케이션이 담당하는 경로를 검사기와 내보내기에 알립니다.
- `tableColumnWidths`가 표 열에 헤더 글자 기준으로 최소 폭을 지정합니다. 절마다 또는 전체에 적용할 수 있어 저자가 쓴 표의 셀에 `<div style>`을 넣을 필요가 없고, HTML 사이트, 쪽을 나누는 형식, Word가 모두 이 값을 따릅니다.
- `ignoreDiagnostics`가 프로젝트가 감수하기로 정한 진단 코드를 조용히 하고, `loadLibrary(…, { cache: true })`가 수집이 바뀌기 전까지 서버가 불러온 라이브러리를 요청 사이에 재사용하게 합니다. 저장된 트리를 읽는 소비자가 `cudocAstVersion: 1`에서 의존할 수 있는 사항을 문서로 적었습니다.
- `cudoc collect --watch`가 문서가 바뀔 때마다 다시 수집하며, 원문이 바뀐 문서만 컴파일하고 그 문서를 읽는 임베드만 다시 해석합니다. `previous` 라이브러리나 준비 결과를 넘기면 어떤 수집기든 같은 절약을 얻고, 컴파일에 실패한 문서는 라이브러리를 깨뜨리는 대신 메시지로 남습니다.
- `cudoc-html`을 `cudoc-export`로 바꿨습니다. 이 패키지가 만드는 것에 맞춘 이름입니다.

### 0.4.0

- `cudoc check`가 문서 집합 전체의 깨진 링크와 앵커와 이미지와 임베드를 한 번에 찾습니다. 명령줄로도 함수로도 쓸 수 있습니다.
- 임베드의 문제를 조용히 넘기지 않고 보고합니다. 렌더링할 수 없는 컴포넌트, 아무것도 찾지 못한 `replace` 규칙, 모르는 키, 파싱되지 않는 블록이며 각각 문서와 줄 번호를 알려 줍니다.
- 제목 ID가 겹칠 때 수집을 멈추지 않고 진단으로 보고합니다.
- 문서를 호스트 선택 중심으로 재편했습니다.
